# RagweedGrid UA: серверна частина

Flask-сервер для сайту [RagweedGrid UA](https://polina33-pilka.github.io/RagweedGrid-UA/).
Приймає координати, бере клімат з Open-Meteo, знаходить частки ріллі й забудови, рахує
індекс придатності моделлю Random Forest і (якщо є ключ) просить Gemini написати пояснення.

Індекс показує, наскільки умови схожі на місця зі знахідками амброзії. Це не ймовірність
того, що рослина там є.

## Що змінювалось

**23.11.2026, поточна версія.** У наборі GBIF «Tracheophyta» траплялися записи роду Ambrosia,
через що кількість візитів у комірках зі знахідками була завищена. Тепер їх прибираємо
до розрахунку візитів і добору фону, модель перенавчена. AUC за просторовою валідацією
виріс з 0,661 ± 0,047 до 0,689 ± 0,046. Висновок той самий: найбільше дає частка забудови,
клімат додає мало.

**18.11.2026, версія для ISEF.** Відповідає презентації й плану дослідження.
Останній коміт до виправлення: [https://github.com/polina33-pilka/RagweedGrid-UA/commit/699b7fcb777326a0b5ba352f782a7ecf5cb214bb].

Суфікси `_v2` і `_v3` у назвах файлів позначають покоління моделі й кліматичної сітки,
до дат вони не мають стосунку.

## Як це рахується

1. Координати округлюються до комірки 0,1°.
2. Рілля й забудова беруться з `landcover_lookup.csv`. Якщо комірки там нема (море чи
   територія поза покриттям), повертається `no_land_data`.
3. Клімат за квітень-жовтень 2015-2024 (температура, опади, вологість) запитується в
   Open-Meteo. Якщо не вийшло, береться найближча точка сітки 0,2° у межах 0,3°.
   У відповіді про це скаже `climate_source`: `live` або `grid`.
4. Модель дає індекс 0-100. Категорії за порогами з `model_v2_meta.json`: нижчі 50 % точок
   карти це низька, наступні 30 % середня, верхні 20 % висока. Перцентиль це частка точок
   карти з меншим значенням.

Ознаки: `temp_mean`, `precip_sum` (мм/добу), `humidity_mean`, `cropland`, `built`.
Модель: Random Forest, 500 дерев.

## Файли в `data/`

- `ambrosia_risk_model_v2.joblib`: сама модель
- `model_v2_meta.json`: ознаки, пороги, місяці сезону, версія scikit-learn
- `risk_map_v2.geojson`: точки карти (1952 точки сітки 0,2°)
- `landcover_lookup.csv`: рілля й забудова по комірках 0,1°
- `full_grid_climate_data_v3.csv`: клімат для запасного варіанта

Усі п'ять файлів мають бути з одного запуску `scripts/16_train_final_model_v2.py`.
Старі й нові між собою не змішувати.

## Ендпоінти

- `GET /api/health` повертає `{"status": "ok"}`
- `GET /api/risk-map` віддає GeoJSON з точками карти
- `POST /api/predict` приймає `{"lat": 50.45, "lon": 30.52}`
- `POST /api/explain` повертає пояснення від Gemini (поля: `explanation`, `groups`,
  `closing`, `fallback`)

Приклад відповіді `/api/predict`:

```json
{
  "lat": 50.45, "lon": 30.52,
  "risk_percent": 93.9,
  "risk_category": "high",
  "percentile": 99,
  "climate": {"temp_mean": 17.9, "precip_sum": 1.5, "humidity_mean": 63.0},
  "climate_source": "live",
  "land": {"cropland": 0.04, "built": 0.37}
}
```

Помилки: `invalid_coords` (400), `outside_ukraine` (422), `no_land_data` (422),
`climate_failed` (502).

## Gemini

Gemini нічого не рахує. Він отримує готові числа й пише одне речення-причину та чотири
поради (комунальні служби, аграрії, мешканці, алергіки). Факти для порад з сайту
Держпродспоживслужби.

У промпті заборонено називати індекс імовірністю чи «ризиком», радити скошування
під час цвітіння, згадувати ліки, гербіциди й дози, казати, що рослина є або відсутня
в точці, і поширювати оцінку на інші країни чи майбутні роки.

Сервер перевіряє, що відповідь це правильний JSON і в ній немає заборонених слів. Якщо ні,
робить до трьох спроб, а потім показує шаблонний текст (`fallback: true`). Без
`GEMINI_API_KEY` завжди буде шаблонний.

## Змінні середовища

- `GEMINI_API_KEY`: ключ з https://aistudio.google.com/apikey (необов'язковий)
- `GEMINI_MODEL`: за замовчуванням `gemini-3.1-flash-lite`
- `FRONTEND_ORIGIN`: адреса сайту для CORS, наприклад `https://polina33-pilka.github.io`
  (`*` лише для тестів)
- `PYTHON_VERSION`: версія Python на Render, `3.11.4`

## Деплой на Render

1. Залий серверну папку (`app.py`, `data/`, `requirements.txt`) у репозиторій на GitHub.
2. На https://render.com обери New, Web Service і підключи репозиторій.
3. Build Command: `pip install -r requirements.txt`, Start Command: `gunicorn app:app`.
4. Додай змінні середовища зі списку вище.
5. Відкрий `/api/health`, там має бути `{"status": "ok"}`. Потім перевір кілька точок через
   `/api/predict` (місто, гори, море, точка за кордоном).
6. Адресу сервісу впиши у фронтенд, в `API_BASE_URL` у `script.js`.

## Локальний запуск

```
pip install -r requirements.txt
$env:GEMINI_API_KEY = "ключ"
python app.py
```

Сервер буде на `http://localhost:5000`.

## Як оновити модель

1. Перенавчити: `scripts/14_cell_level_background.py`, потім `16_train_final_model_v2.py`.
2. Скопіювати п'ять файлів з `data/processed/` у `data/` серверної папки.
3. Закомітити їх разом із `requirements.txt` одним комітом, щоб модель, пороги й карта
   не розійшлися.
4. Дочекатися деплою й перевірити `/api/health`.

## Обмеження

- Безкоштовний Render засинає після 15 хв без запитів, перший запит після цього може
  займати до хвилини. Перед демонстрацією зроби один тестовий.
- Усі запити до Open-Meteo йдуть з одного сервера, тому ліміт спільний. При великому
  навантаженні частіше працюватиме запасна сітка.
- Під час навчання клімат для комірки 0,1° брався з найближчої точки сітки 0,2°, а на
  сайті запитується для центра комірки. Тому для окремих точок можливі невеликі відмінності.
- Індекс не підтверджує наявність амброзії й не прогнозує пилок. За межами України
  модель застосовувати не варто.
