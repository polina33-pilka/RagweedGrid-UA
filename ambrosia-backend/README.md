# RagweedGrid UA: серверна частина

Flask-сервер для сайту [RagweedGrid UA](https://polina33-pilka.github.io/RagweedGrid-UA/):
оцінка придатності території України для амброзії полинолистої.
Сервер приймає координати, бере клімат з Open-Meteo, знаходить частки ріллі й забудови,
рахує індекс моделлю Random Forest і за потреби просить Gemini сформулювати пояснення.

Індекс є відносною оцінкою схожості умов на місця зі знахідками, а не ймовірністю
наявності рослини.

## Журнал змін

**23.11.2026, виправлення розрахунку візитів (поточна версія).**
Набір GBIF «Tracheophyta» містив і записи роду Ambrosia, тому в комірках зі знахідками
кількість візитів була завищена. Тепер ці записи виключаються перед розрахунком візитів
і добором фону, модель перенавчено. AUC за просторовою валідацією: 0,689 ± 0,046
(було 0,661 ± 0,047). Висновки не змінилися: головний внесок дає частка забудови,
клімат додає мало.

**Станом на 18.11.2026, версія, подана на ISEF.** Відповідає презентації й плану дослідження.
Останній коміт до виправлення: [].

Суфікси `_v2` і `_v3` у назвах файлів (`ambrosia_risk_model_v2.joblib`,

## Як працює розрахунок

1. Координати округлюються до комірки 0,1°.
2. Частки ріллі й забудови беруться з `landcover_lookup.csv`. Якщо комірки там немає
   (море, поза територією покриття), сервер повертає помилку `no_land_data`.
3. Клімат за квітень–жовтень 2015–2024 (середня температура, середні добові опади,
   відносна вологість) запитується в Open-Meteo для центра комірки. Якщо запит не вдався,
   береться найближча точка підготовленої сітки 0,2° у межах 0,3°; у відповіді це
   `climate_source: "grid"`, інакше `"live"`.
4. Модель повертає індекс 0–100. Категорія визначається порогами з `model_v2_meta.json`
   (нижні 50 % точок карти нижча, наступні 30 % середня, верхні 20 % вища), перцентиль
   показує частку точок карти з нижчим значенням.

Ознаки моделі: `temp_mean`, `precip_sum` (середні добові опади, мм/добу), `humidity_mean`,
`cropland`, `built`. Random Forest, 500 дерев.

## Файли в `data/`

`ambrosia_risk_model_v2.joblib` — навчена модель 
`model_v2_meta.json` — ознаки, пороги категорій, місяці сезону, версія scikit-learn 
`risk_map_v2.geojson` — точки карти (1952 точки сітки 0,2°) 
`landcover_lookup.csv` — частки ріллі й забудови для комірок 0,1° 
`full_grid_climate_data_v3.csv` — клімат для запасного варіанта 

Усі п'ять файлів мають бути з одного запуску `scripts/16_train_final_model_v2.py`.
Змішувати старі й нові файли не можна.

## Ендпоінти

**`GET /api/health`**: `{"status": "ok"}`.

**`GET /api/risk-map`**: GeoJSON з точками карти (`risk_percent`, `risk_category`).

**`POST /api/predict`**: тіло `{"lat": 50.45, "lon": 30.52}`. Відповідь:

```json
{
  "lat": 50.45, "lon": 30.52,
  "risk_percent": 93.9,
  "risk_category": "high",
  "percentile": 99,
  "climate": {"temp_mean": 17.9, "precip_sum": 1.5, "humidity_mean": 63.0},
  "climate_source": "live",
  "land": {"cropland": 0.04, "built": 0.37}
}
```

Помилки: `invalid_coords` (400, немає числових `lat`/`lon`), `no_land_data` (422),
`climate_failed` (502, клімат недоступний і поблизу немає точки сітки).

**`POST /api/explain`**: тіло містить `lang` (`uk` або `en`), `lat`, `lon`, `risk_percent`,
`percentile`, `risk_category`, `climate`, `land`, `placeName`. Відповідь: `explanation`,
`groups` (чотири групи порад), `closing` (фіксоване застереження), `fallback` (`true`, якщо
показано шаблонний текст).

## Пояснення від Gemini

Gemini отримує вже готові числа й формулює одне речення з поясненням та чотири поради
(комунальні служби, аграрії, мешканці, алергіки). Він нічого не рахує.
Факти для порад узято зі сторінок Держпродспоживслужби про амброзію.

У промпті заборонено:
- називати індекс імовірністю або «ризиком»;
- радити скошування під час цвітіння;
- згадувати лікарів, ліки, назви гербіцидів і дози;
- стверджувати, що рослина є або відсутня в точці, говорити про концентрацію пилку,
  пропонувати використовувати результат для карантинних меж чи вибору засобу обробки;
- поширювати оцінку на інші країни й майбутні роки.

Сервер перевіряє, що відповідь є коректним JSON з полем `reason` і чотирма непорожніми
порадами та що в ній немає заборонених слів. Якщо перевірка не пройдена, робиться до трьох
спроб, після чого повертається шаблонний текст (`fallback: true`). Без `GEMINI_API_KEY`
працює тільки шаблонний текст.

## Змінні середовища

`GEMINI_API_KEY` — ключ з https://aistudio.google.com/apikey (необов'язковий, без нього лише шаблонні пояснення) 
`GEMINI_MODEL` — назва моделі, за замовчуванням `gemini-3.1-flash-lite` 
`FRONTEND_ORIGIN` — адреса сайту для CORS, напр. `https://polina33-pilka.github.io`; `*` лише для тестів 
`PYTHON_VERSION` — версія Python на Render, `3.11.4` 


## Деплой на Render

1. Завантаж серверну папку (з `app.py`, `data/` і `requirements.txt`) у репозиторій на GitHub.
2. На https://render.com: New → Web Service, підключи репозиторій.
3. Build Command: `pip install -r requirements.txt`. Start Command: `gunicorn app:app`.
4. Додай змінні середовища з таблиці вище.
5. Після деплою відкрий `/api/health`: має бути `{"status": "ok"}`. Потім перевір кілька точок
   через `/api/predict` (місто, гори, море, точка за кордоном).
6. Адресу сервісу вкажи у фронтенді (`API_BASE_URL` у `script.js`).

## Локальний запуск

```
pip install -r requirements.txt
$env:GEMINI_API_KEY = "ключ"    
python app.py
```

Сервер: `http://localhost:5000`.

## Оновлення моделі

1. Перенавчити (`scripts/14_cell_level_background.py`, потім `16_train_final_model_v2.py`).
2. Скопіювати п'ять файлів із `data/processed/` у `data/` серверної папки.
3. Закомітити їх разом із `requirements.txt` одним комітом, щоб модель, пороги й карта
   лишалися узгодженими.
4. Дочекатися повторного деплою й перевірити `/api/health`.

## Обмеження

- Безкоштовний тариф Render засинає після 15 хв без запитів; перший запит після простою
  займає до хвилини. Перед демонстрацією зроби один тестовий запит.
- Запити до Open-Meteo йдуть з одного сервера, тому їхні безкоштовні ліміти спільні для всіх
  користувачів. За великого навантаження частіше спрацьовуватиме запасний варіант із кліматом
  найближчої точки сітки.
- Під час навчання клімат для комірки 0,1° береться з найближчої точки сітки 0,2°, а на сайті
  запитується для центра комірки, тому для окремих точок можливі невеликі відмінності.
- Індекс не підтверджує наявність амброзії й не прогнозує рівень пилку. Модель не варто
  застосовувати за межами України.
